# 架构说明

## 数据来源

站点：https://wiki.biligame.com/nrc/（BWiki，MediaWiki 1.37.0）

精灵数据并非存在 HTML 里，而是存在站点的 Lua 数据模块中，由页面模板通过 `#invoke` 渲染。
因此爬虫直接通过 MediaWiki API 拉取模块源码，解析 Lua 表字面量，得到结构化数据。

关键模块：

| 模块 | 内容 |
|------|------|
| `Module:Pets/data/Catalog` | 精灵基础数据：编号、名称、种族值、属性、阶段、形态、进化链 ID |
| `Module:Pets/data/Evolutions` | 进化链：主进化线（chain）+ 领主化分支（lord_branches） |
| `Module:Pets/data/Skills` | 技能数据（技能名、类别、属性、物攻/魔攻、威力、能耗、描述） |
| `Module:Pets/data/Learnsets` | 每只精灵的可学习技能（升级、血脉、技能石、特性技能） |
| `Module:Pets/data/Types` | 属性克制数据 |
| `Module:Natures/data` | 性格数据（30 种性格的提升/降低项） |
| `Module:Pets/data/TrainingReference` | 养成参考（用于交叉核对性格语义） |

## 获取方式

```
GET /api.php?action=parse&page=Module:Pets/data/Catalog&prop=wikitext&format=json
```

必须携带浏览器 `User-Agent` 与 `Referer` 请求头，否则被腾讯 EdgeOne 防护拦截（返回 567）。

## 数据流

```
api.php (wikitext)  →  LuaParser（递归下降解析 Lua 表）
                          ├─ Catalog + Evolutions → 关联（通过 evolution_id）→ data/pets.csv
                          ├─ Types                → data/type_relations.csv / data/type_multipliers.csv
                          ├─ Skills               → data/skills.csv
                          ├─ Learnsets + Catalog  → data/learnsets.csv（按精灵展开）
                          └─ Natures/data         → data/natures.csv

data/*.csv  →  roco_calc.py（查询 + 面板 + 伤害）  →  calc.py（命令行 / JSON）
```

## Lua 表结构

### Catalog（每只精灵一个条目）

```lua
pet_000050 = {
  name = "一窝蜂",
  number = "082",            -- 图鉴编号（形态变体会共享同一编号）
  stats = { atk=32, def=27, hp=87, spa=29, spd=27, spe=26 },
  types = { "虫系", "翼系" },
  stage = 1,                 -- 进化阶段：1 初始 → 2/3 进化 → 4 领主化
  form = "",                 -- 形态（基础形态为空，变体如"首领形态"）
  evolution_id = "evolution_bf682d603e12",
  ...
}
```

### Evolutions（一个 id 可能对应多条分支线）

```lua
evolution_bf682d603e12 = {
  { chain = { {id="pet_000050", stage=1, ...}, {id="pet_000051", stage=2, ...}, {id="pet_000143", stage=3, ...} },
    lord_branches = { {id="pet_000548", stage=4, ...} },   -- 领主化分支
    name = "一窝蜂进化链" },
}
```

- `chain`：主进化线（stage 1→2→3），正常进化。
- `lord_branches`：领主化分支（stage 4），通过道具首领化，**与前身共享图鉴编号**。
- 御三家（如迪莫）有多个领主化分支，即数组里含多个 `{chain, lord_branches}` 元素。

## CSV 输出 schema（data/pets.csv）

| 字段 | 含义 | 示例 |
|------|------|------|
| `number` | 精灵编号 | `082` |
| `name` | 名称（中文） | `一窝蜂` |
| `hp` | 生命种族值 | `87` |
| `atk` | 物攻种族值 | `32` |
| `def` | 物防种族值 | `27` |
| `spa` | 魔攻种族值 | `29` |
| `spd` | 魔防种族值 | `27` |
| `spe` | 速度种族值 | `26` |
| `types` | 属性（多个用 `\|` 分隔） | `虫系\|翼系` |
| `stage` | 进化阶段 | `1` |
| `form` | 形态（基础形态为空） | `首领形态` |
| `evolution_chain` | 进化链（名称序列，`→` 连接） | `一窝蜂→黄蜂后→花魁蜂后→女王蜂(首领形态)` |

> 进化链用名称而非编号，是因为领主化形态与前身共享编号，编号序列会出现 `084→084` 的歧义。

## 进化链语义（重要）

进化链只写到**该精灵自身为止**，分叉点之后的形态不展开：

- 迪莫 → `迪莫`（起点，不向后展开）
- 圣光迪莫 → `迪莫→圣光迪莫(首领形态)`
- 女王蜂 → `一窝蜂→黄蜂后→花魁蜂后→女王蜂(首领形态)`

规则：

1. 对每条分支线，某成员的进化链 = 该分支线从起点到它自身（含）的成员序列。
2. 分叉点（如迪莫有 4 个领主化分支）之后的形态各自独立成线，不会拼成一串。
3. `form` 非空的成员以 `name(form)` 形式显示（如 `女王蜂(首领形态)`）。

## 属性克制数据（第二步）

数据来源：`Module:Pets/data/Types`（游戏实际数据，权威）。

模块结构（防御方视角）：

```lua
{ ["光系"] = { weak={{multiplier=2,type="草系"},...}, resist={{multiplier=0.5,type="恶系"},...} },
  ["光系|地系"] = { weak={{multiplier=3,type="草系"},...}, resist={{multiplier=0.5,type="普通系"},...} } }
```

- `weak`：该属性组合「被克制」——被 `type` 攻击时伤害 ×`multiplier`。
- `resist`：该属性组合「被抵抗」——被 `type` 攻击时伤害 ×`multiplier`。

共 18 个单属性 + 102 个双属性组合，倍率 4 档：

| 情形 | 倍率 |
|------|------|
| 单克制（攻击属性克制一个防御属性） | ×2 |
| 双克制（攻击属性克制两个防御属性） | ×3 |
| 单抵抗 | ×0.5 |
| 双抵抗 | ×0.25 |
| 无关系 | ×1（不显式存储） |

> 注意：双克制是 ×3 而非乘算的 ×4，与部分第三方攻略（写 ×4）不一致，以 wiki 数据为准。

### 输出文件

**`data/type_relations.csv`**（单属性二元组，113 行）

| 字段 | 含义 |
|------|------|
| `attack` | 攻击方属性 |
| `defend` | 被攻击方属性 |
| `relation` | `克制`（×2）或 `抵抗`（×0.5） |

**`data/type_multipliers.csv`**（完整倍率表，1023 行，含双属性组合）

| 字段 | 含义 |
|------|------|
| `defend` | 防御方属性组合（如 `光系` 或 `光系\|地系`） |
| `attack` | 攻击方属性 |
| `multiplier` | 倍率（0.25 / 0.5 / 2 / 3） |

伤害计算器查表：给定攻击属性 a 与防御属性组合 d，在 `type_multipliers.csv` 查 `(defend=d, attack=a)`，命中则取 `multiplier`，否则 ×1。

## 与第三方攻略的交叉验证

最初按需求爬取 ali213 攻略页，与 wiki 数据对比发现：

- 抵抗关系：63 组完全一致。
- 克制关系：攻略 49 组，wiki 50 组，唯一差异是「草系→光系」——攻略草系条目漏写，wiki 确认草克制光。

故最终改用 wiki `Types` 模块为权威数据源。

```lua
  element = "翼系",

  game_id = 7150060,
}
```

输出字段：

| 字段 | 含义 |
|------|------|
| `skill_id` | 模块内键名，如 `skill_000688` |
| `game_id` | 游戏内技能 ID |
| `name` | 技能中文名 |
| `category` | 攻击 / 状态 / 防御 / 特性 |
| `element` | 技能属性；状态/特性类可能为 `无系别` |

> 少数技能的威力随规则变化（如魔能爆、怨力打击、砂糖弹球），数据里的 `power` 可能是 1 或固定档位。计算这类技能时需要用 `--power` 手动指定实际威力。

### Natures 模块

数据来源：`Module:Natures/data`，输出 `data/natures.csv`。

模块结构：

```lua
{ stats = { {id=80,name="物攻"}, {id=82,name="物防"}, ... },
  rows  = { {id=1, name="大胆", up=80, down=82}, ... } }
```

- 30 种性格，每种都是「一项提升、一项降低」。
- 能力编号映射由模块自带的 `stats` 表给出：`79=生命`、`80=物攻`、`81=魔攻`、`82=物防`、`83=魔防`、`84=速度`。
- 已用 `Module:Pets/data/TrainingReference` 的 `labels.nature` 逐条核对，30 条完全一致。

> 注意：洛克的性格语义和宝可梦不完全一样。例如洛克的「大胆」是 **物攻↑ / 物防↓**，不是宝可梦的「防御↑ / 攻击↓」。

## 可学习技能表（第十四步）

数据来源：`Module:Pets/data/Learnsets`（学习表）+ `Module:Pets/data/Catalog`（把学习表挂到精灵上），输出 `data/learnsets.csv`。

模块结构（每只精灵或每个形态一个学习表）：

```lua
learnset_xxxx = {
  native_skills = { {level=8, skill="skill_000001", stage=1}, ... },  -- 升级学习
  blood_skills  = { {blood="水", level=15, skill="skill_000002"}, ... }, -- 血脉技能
  skill_stones  = { "skill_000003", ... },                              -- 技能石
  feature_skill = "skill_000004",                                       -- 自带特性技能
}
```

输出是「一只精灵 + 一个技能」一行，同一技能来自多个来源时合并成一行：

| 字段 | 含义 |
|------|------|
| `pet_id` | Catalog 内的精灵 ID |
| `number` / `name` / `form` / `stage` | 与 `data/pets.csv` 相同的精灵标识 |
| `skill_id` / `skill_name` | 技能 ID 和中文名 |
| `category` / `element` / `damage_class` / `power` | 从 `data/skills.csv` 带过来的技能信息 |
| `sources` | 学习来源，多个用竖线分隔：`native` 升级、`blood` 血脉、`stone` 技能石、`feature` 特性技能 |
| `level` | 升级/血脉学习的最低等级；技能石和特性技能为空 |
| `blood` | 血脉技能对应的属性，多个用竖线分隔 |

匹配方式：先按「编号 + 名称 + 形态 + 阶段」精确匹配；老数据的形态名可能变化，再退到「编号 + 名称 + 阶段」，但要求候选条目的学习表完全相同，避免把不同形态的技能混在一起。所有 621 只精灵都匹配成功。

当前数据共 **31,347 行**，覆盖 **817 个不同技能**，其中攻击技能 **16,715 行**。每只精灵的攻击技能最少 9 个、最多 281 个（学院呱呱有大量技能石）。升级学习的最低等级都 ≤51，所以 60 级 PVP 下全部可用。

已知缺口：

- 27 个 `dc5a_*` 技能 ID 在 `data/skills.csv` 里找不到（共 201 条引用，全部来自技能石），已跳过；等技能表更新后再重跑。
- Catalog 有 12 个条目不在 `data/pets.csv` 里（云梦豚、长江豚，以及护主犬/音速犬等的新形态），本表没有写入；需要先更新精灵表。

## 面板值公式（第四步）

默认按 **60 级 PVP** 计算，可用 `--level` 改等级。

记：

- `B`：该项种族值
- `T`：该项天分，只能是 0、7、8、9、10
- `L`：等级
- `N`：性格乘区（提升项 1.2，降低项 0.9，其余 1.0）

### 非生命

```text
内层 = 内层取整((L/100 + 0.5) × (B + 3T))
面板 = round((内层 + 10) × N) + 50
```

### 生命

```text
内层 = 内层取整((L/50 + 0.5) × (B + 3T))
面板 = round((内层 + L + 10) × N) + 100
```

### 取整规则

- `round` 模拟 JavaScript 的 `Math.round`：恰好 .5 时向正无穷方向进一位（不是 Python 默认的「半到偶数」）。
- `内层取整` 在 **天分 T = 0 且数值恰好是 .5** 时使用「半到奇数」：整数部分是偶数就进一位，是奇数就保留；其余情况用普通四舍五入。
- 这个细节只在极端边界上差 1 点，但为了和参考计算器完全一致，照原样实现。

### 校验

- 岚鸟物攻种族 128、天分 10 → 物攻面板 **234**。
- 奇丽花物防种族 121、天分 10 → 物防面板 **226**。
- 这两组数字来自公开文章，和本实现一致。

### 取整口径的选择

三个社区计算器的面板公式在「什么时候取整」上不完全一样：

- tzrain（用户指定参考）：先对内层取整，再乘性格，再取整。
- rocokingdom：整个括号算完后只取整一次。
- roco.pet：先取整，再乘性格，但天分记法不同（0–60，约等于 6 倍天分）。

在性格不是「不加不减」时，tzrain 和 rocokingdom 约有 18% 的数值会差 1 点。本项目 **以 tzrain 为准**，因为它是用户指定的参考实现；如果以后拿到游戏内实测面板，可以用实测值再校准。

## 伤害公式（第五步）

记：

- `BP`：技能基础威力（可用 `--power` 覆盖）
- `weather`：天气对基础威力的倍率；目前只有「雨天 + 水系技能」为 1.75，其余为 1.0
- `flat`：固定威力加成
- `power_pct`：威力百分比加成
- `damage_flat`：只影响伤害的固定威力加成
- `damage_pct`：只影响伤害的威力百分比加成
- `STAB`：本系加成，技能属性在攻击方属性里为 1.25，否则 1.0
- `type`：属性克制倍率，查 `data/type_multipliers.csv`，未命中为 1.0
- `misc`：其他乘区，默认 1.0
- `stage`：攻防乘区（攻防等级 + 增减益层数），默认 1.0
- `reduction`：减伤乘区，默认 1.0
- `final`：最终伤害乘区，默认 1.0（百分比 100，范围 0–500）

### 计算顺序

```text
天气基础威力 = floor(BP × weather)          # 没有天气时 weather = 1，不取整
有效威力 = max(0, (天气基础威力 + flat) × (1 + power_pct/100))
伤害威力 = max(0, (有效威力 + damage_flat) × (1 + damage_pct/100))

显示威力（未取整） = 伤害威力 × STAB × type × misc × stage
显示威力（界面）   = round(显示威力（未取整）)

等级系数 = (45 × L/100 + 10) / 41        # 60 级 = 37/41

单次伤害 = floor(
    round(攻击面板 × 显示威力（未取整） × reduction × 等级系数) / 防御面板
)

总伤害 = floor(单次伤害 × 连击次数 × final)
```

**关键：伤害公式使用未取整的显示威力。** 界面上的显示威力仍然四舍五入，方便阅读；但进入伤害公式的是带小数的原值。这个结论来自下面的游戏内实测。

### 攻防等级乘区

`attack_mod` 和 `defense_mod` 是百分比（例如 `--attack-mod 50` 表示增攻 50%，`--defense-mod -50` 表示减防 50%）：

```text
分子 = 1 + max(attack_mod, 0)/100 + max(-defense_mod, 0)/100
分母 = 1 + max(-attack_mod, 0)/100 + max(defense_mod, 0)/100
stage = 分子 / 分母
```

### 增减益层数（第八步）

游戏里的属性增减益按层计算。用户确认的换算规则：

- 物攻、物防、魔攻、魔防：每层 = **10 个百分点**。
- 速度：每层 = **固定 +10 点**，不按百分比。
- 正数表示增益，负数表示减益。

伤害只使用当前技能走的通道：

- 物攻技能：攻方物攻层数、受击方物防层数。
- 魔攻技能：攻方魔攻层数、受击方魔防层数。
- 另一条通道的层数不参与本次伤害。

层数先换成百分比，再和 `--attack-mod` / `--defense-mod` 相加，然后套用上面的公式：

```text
attack_mod  = 手动攻方百分比 + 攻方对应层数 × 10
defense_mod = 手动守方百分比 + 守方对应层数 × 10

攻防乘区 = (10 + 增攻层数 + 减防层数) / (10 + 减攻层数 + 增防层数)
```

例如攻方魔攻 +2 层、守方魔防 −1 层：

```text
攻防乘区 = (10 + 2 + 1) / 10 = 1.3
```

速度层数不影响伤害，结果里会给出 `attacker_speed_after_buffs` / `defender_speed_after_buffs`，即「面板速度 + 层数 × 10」，供以后做出手顺序时使用。层数范围先限制在 −99～99，只是防止输入错误，不代表游戏上限。

验证示例（水灵魔攻 270，龙息帕尔魔防 156，气泡威力 100）：

| 增减益 | 攻防乘区 | 计算用威力 | 伤害 |
|--------|----------|------------|------|
| 无 | ×1 | 125 | 195 |
| 魔攻 +2 层 | ×1.2 | 150 | 234 |
| 魔防 −1 层（守方） | ×1.1 | 137.5 | 214 |
| 魔攻 +2、魔防 −1 | ×1.3 | 162.5 | 253 |

### 星陨印记（第九步）

游戏词条：「使用非幻系技能攻击拥有此印记的精灵时，会触发星陨印记，消耗全部星陨层数，对其造成额外的幻系伤害。」

本实现的触发条件：

- 受击方有星陨层数（输入范围 0～99 的正整数）。
- 本次技能不是幻系，且是物攻/魔攻的直接伤害技能。
- 每次行动只触发一次；触发后层数全部消耗，结果为 0 层。

计算公式（照 tzrain 的两次取整）：

```text
星陨基础威力 = 层数² + 24×层数 − 24          # 小于 0 时按 0
星陨显示威力 = round(星陨基础威力 × 幻系克制)
攻防调整后威力 = round(星陨显示威力 × 攻防乘区)
星陨伤害 = floor(
    round(攻方对应攻击 × 攻防调整后威力 × 减伤 × 等级系数) / 受击方对应防御
) × 最终乘区，再向下取整
```

- 使用与触发技能相同的通道：物攻技能用物攻/物防，魔攻技能用魔攻/魔防。
- 不乘本系加成、不乘其他乘区（`misc_multiplier`）、不乘连击次数。
- 增减益层数通过「攻防乘区」参与星陨伤害。
- 总伤害 = 技能伤害 + 星陨伤害；能否击倒也按总伤害判断。

层数对应数值：

| 层数 | 基础威力 | 水灵气泡打帕尔的额外伤害 | 总伤害（技能 195） |
|------|----------|--------------------------|--------------------|
| 1 | 1 | 1 | 196 |
| 2 | 28 | 43 | 238 |
| 3 | 57 | 89 | 284 |
| 5 | 121 | 188 | 383 |
| 10 | 316 | 493 | 688 |

**取整差异（待游戏实测）**：tzrain 在「基础威力 × 克制」后取整，本实现照做。但普通技能的实测结论是「伤害使用未取整的威力」，两者在星陨上可能不同。一个能明确区分两种做法的例子：

```bash
python calc.py --attacker 水灵 --attacker-nature 聪明 \
  --attacker-talents "魔攻=10" --defender 迪莫 --skill 气泡 \
  --starfall-layers 3
```

迪莫是光系，幻系克制 ×0.5，3 层基础威力 57：

- 按 tzrain 先取整：round(57 × 0.5) = 29，星陨额外伤害 **40**，总伤害 **214**。
- 若不取整：57 × 0.5 = 28.5，星陨额外伤害 **39**，总伤害 **213**。

游戏里显示 214 就说明 tzrain 的取整对；显示 213 就要改成保留小数。已记入 `docs/todo.md`。

### 属性克制

- 单克制 ×2，双克制 ×3；单抵抗 ×0.5，双抵抗 ×0.25；一克一抗 ×1；无关系 ×1。
- 双属性组合的键名顺序由 `crawl_type_chart.py` 决定；`roco_calc.type_multiplier()` 会按同样顺序规范化。
- 已用 tzrain 内置的 18×18 属性表逐条比对：`data/type_multipliers.csv` 的 1023 条全部一致。

### 校验

公开文章实例：

```text
岚鸟（物攻 128，天分 10）→ 物攻面板 234
奇丽花（物防 121，天分 10）→ 物防面板 226
扇风（翼系，物攻，有效威力 142.5）
本系 ×1.25，打草系 ×2
显示威力 = round(142.5 × 1.25 × 2) = 356
单次伤害 = floor(round(234 × 356 × 37/41) / 226) = 332
```

本实现输出的显示威力和伤害分别是 **356 / 332**，与文章一致。

### 游戏内实测：雨天与取整顺序

2026-11-21 用游戏内同一只水灵（聪明性格、魔攻天分 10，魔攻面板 270）打龙息帕尔（魔防面板 156）实测：

| 技能 | 场景 | 基础威力 | 伤害 |
|------|------|----------|------|
| 气泡 | 无雨 | 100 | 195 |
| 气泡 | 雨天 | floor(100 × 1.75) = 175 | 341 |
| 水炮 | 无雨 | 110 | 214 |
| 水炮 | 雨天 | floor(110 × 1.75) = 192 | 374 |

这四个数字同时证明了两个细节：

1. **伤害公式不先四舍五入显示威力。** 水炮无雨显示威力是 137.5；如果先取整成 138，伤害会是 215，而游戏是 214。
2. **雨天先把基础威力乘以 1.75，再向下取整。** 水炮雨天基础威力是 floor(110 × 1.75) = 192；如果先四舍五入成 193，伤害会是 376，而游戏是 374。

因此 `calculate_damage()` 的返回值里同时有：

- `display_power`：界面显示用的整数（四舍五入）。
- `display_power_raw`：伤害公式实际使用的未取整值。
- `weather_base_power`：天气修正后的基础威力。

雨天目前只在 `weather="雨天"` 且技能为水系时生效；沙暴、暴风雪、雷鸣、霞光梦境只作为文本显示，不改变伤害。

> 待确认：雨天 +75% 与蓄势印记 +30%、攻击印记 +10% 等威力加成，是加在同一个「基础威力桶」里，还是分开相乘。当前实现按天气先作用于基础威力处理；印记相关测试见 `docs/todo.md`。

### 没有暴击和随机浮动

参考实现和公开资料中，PVP 伤害公式没有暴击乘区和随机浮动。本实现也不加入这两个因素。

## 范围推断（第十步）

对方精灵的性格、天分在战前未知，`roco_analysis.py` 不再六项分开猜，而是给整只精灵维护一个候选集合：

```text
性格：30 种，每种恰好一个提升项、一个降低项
天分：6 项各取 0 / 7 / 8 / 9 / 10，至少 1 项、至多 3 项非 0
      6×4 + 15×4² + 20×4³ = 24 + 240 + 1280 = 1,544 种
整体候选：30 × 1,544 = 46,320 种
```

这样“性格只能提升一项”“天分最多三项”会在过滤记录时自动生效。例如已确认魔防和生命都不受性格影响，性格的提升/降低项就只能从另外四项里选，可能性格从 20 种缩到 12 种。

实现：

- 每个候选固定编号 = 性格序号 × 1,544 + 天分序号。
- 每项属性的每个取值（最多 15 个）预先算好位图，第 i 位表示候选 i 的该项等于该值。
- 一条伤害记录：对剩余候选的物防/魔防取值逐个套用伤害公式，保留总伤害等于记录值的取值，再做一次位图求交。
- 一条生命百分比记录：对剩余生命取值逐个计算 `round((生命 − 累计伤害) ÷ 生命 × 100)`，保留等于记录值的取值。
- 记录对不上时不缩小范围，只在 `warnings` 和该条记录结果里提示。
- 结果里的最低/最高值和“能否击倒”用剩余候选的边界值计算；生命占比取“最小伤害 ÷ 最大生命”和“最大伤害 ÷ 最小生命”。

接口和字段见 `docs/frontend-design.md` 第 5 节；命令行演示见 `analyze.py`：

```bash
# 初始范围：帕尔魔防 145～217，气泡伤害 140～210
python analyze.py --our 水灵 --nature 聪明 --talent 魔攻=10 \
  --opponent 龙息帕尔 --skill 气泡

# 记录雨天 341 后：魔防锁定 156
python analyze.py --our 水灵 --nature 聪明 --talent 魔攻=10 \
  --opponent 龙息帕尔 --skill 气泡 --weather 雨天 --observe 341

# 再记录“195 伤害后显示 50%”：生命锁定 391，剩 4,416 种候选、12 种性格
python analyze.py --our 水灵 --nature 聪明 --talent 魔攻=10 \
  --opponent 龙息帕尔 --skill 气泡 --weather 雨天 \
  --observe 341 --observe hp:50:195
```

## 6 对 6 队伍推断（第十五步）

新增 `roco_team.py`，和单只精灵的 `roco_analysis.analyze_battle` 并存；旧的命令行、网页接口和测试都不改。队伍版的目标是：双方各 6 个位置，我方全部已知，对方每只精灵分别推断可能的性格、天分和当前生命。

### 输入

```json
{
  "level": 60,
  "weather": null,
  "hp_percent_rounding": "round",
  "our_team": [
    {
      "pet": "水灵",
      "nature": "聪明",
      "talents": {"spa": 10},
      "skills": ["气泡", "水炮", "天洪", "水弹枪"],
      "current_hp": 306,
      "buffs": {},
      "starfall_layers": 0
    }
  ],
  "opponent_team": [
    {
      "pet": "龙息帕尔",
      "skills": ["龙之利爪", "升龙咆哮"],
      "buffs": {},
      "starfall_layers": 0
    }
  ],
  "active_our_slot": 0,
  "active_opponent_slot": 0,
  "records": []
}
```

- 队伍列表最多 6 项，不足 6 项时输出里会补成 6 个位置；没有 `pet` 的位置视为空位。
- 我方每个位置最多 4 个技能；对方技能数量不限。
- 我方 `current_hp` 是具体数字，不填则默认满血；对方没有这个字段，默认满血，要从战斗中途开始记录就先加一条生命变化记录。
- 技能可以写成名称，也可以写成 `{"name": "魔能爆", "power": 120}` 来临时指定威力，或加 `"hits"` 指定连击。

### 两种记录

伤害记录：

```json
{
  "type": "damage",
  "attacker_side": "our",
  "attacker_slot": 0,
  "defender_side": "theirs",
  "defender_slot": 0,
  "skill": "气泡",
  "damage": 195,
  "hp_percent": 50
}
```

- `attacker_side` / `defender_side` 取 `our` 或 `theirs`，两边必须是不同阵营。
- 受击方是对方时，可以加 `hp_percent`，表示打完后对方血条显示的剩余百分比；它会同时缩小最大生命和当前生命。
- 受击方是我方时，可以加 `remaining_hp`，表示打完后我方剩余的具体生命值；不接受 `hp_percent`。
- 记录里的 `weather`、`attacker_buffs`、`defender_buffs`、`starfall_layers` 是可选的“当时状态”快照；不填就沿用当前状态。

生命变化记录：

```json
{"type": "hp_change", "side": "theirs", "slot": 0,
 "hp_percent": 80, "hp_delta": 116}

{"type": "hp_change", "side": "our", "slot": 0, "hp": 306}
```

- 对方：`hp_percent` 必填；`hp_delta` 选填，正数表示回血、负数表示掉血。
  - 不填 `hp_delta`：只把当前生命重置到显示该百分比的范围，不额外缩小性格/天分。
  - 填了 `hp_delta`：用「变化前生命 + 变化量 = 变化后生命」再筛选候选，可能锁定最大生命和当前生命。
- 我方：直接填 `hp` 具体生命值，不接受百分比。

### 推断规则

- 同一只对方精灵的所有记录按输入顺序处理；不同位置完全独立，打位置 1 不会影响位置 2。
- 伤害记录先按受击方对应的防御（对方防守）或攻击（对方进攻）筛选候选，再扣掉这次伤害。
- 对方初始满血。攻击记录里的剩余百分比可以用来反推最大生命；生命变化记录用来处理回血、掉血等没有被追踪的变化。
- 一条记录完全没有候选能对上时，不修改上一步结果，只在 `records[].matched` 标为 `false` 并在 `warnings` 里说明。
- 我方生命始终是具体数字；对方的当前生命同时给出具体范围和显示百分比范围。

### 输出

`analyze_team(state)` 返回：

- `our_team` / `opponent_team`：固定 6 个位置，未选择的位置 `configured: false`。
- `opponent_team[i].stats`：六项属性的最小值、最大值和所有可能取值；`builds` 是剩余/总候选数；`natures_remaining` 和 `possible_natures` 是可能性格。
- `opponent_team[i].current_hp` 是具体生命范围，`current_hp_percent` 是显示百分比范围。
- `active`：当前对位双方的技能伤害表。
  - `our_skills[]` 给出伤害范围、对方剩余生命百分比范围、占最大生命百分比和能否击倒。
  - `opponent_skills[]` 给出伤害范围、我方剩余具体生命范围和能否击倒；不出现我方百分比。
- `records`：每条记录的处理结果，顺序与输入一致；`warnings`：没有对上或被跳过的说明。

### 实现方式

复用 `roco_analysis.py` 的 46,320 个候选和位图过滤，不另写一套性格/天分公式。每个候选额外保存当前生命的上下界；伤害只按受击方防御或攻击的 15 个不同取值模拟，再映射回候选。这样一条记录仍然只需几次位图运算加一遍 46,320 个候选的遍历。

技能伤害表避免让 46,320 乘以技能数量：

- 伤害范围只用该项属性的 15 个可能取值计算，不逐个候选模拟。
- 剩余生命百分比同时取决于最大生命、防御和当前生命。先把候选按「最大生命 + 防御 + 当前生命上下界」合并成小组，同一组只算一次；当前对位的所有技能共用这一份分组，所以候选数不会乘以技能数。
- 位图枚举改为逐字节查表，筛选后的新位图用字节数组一次生成，避免反复操作几万位的大整数。
- 没有被打过的对方精灵直接按满血汇总，不再遍历 46,320 个候选。

### 网页接口

- `POST /api/team`：没有 `battle_log` 时，请求体就是 `analyze_team(state)` 的输入；带 `battle_log` 和 `active_our_slot` / `active_opponent_slot` 时，调用 `analyze_battle_active`，用对局推断范围和当前状态计算所选对位。
- `GET /api/meta`：在原来的精灵、性格、攻击技能之外，每只精灵多一个 `skills` 字段，列出它能学的攻击技能，供页面过滤下拉选项；每只精灵另有 `avatar`，每个攻击技能另有 `icon`，指向本机图片。
- `GET /assets/...`：返回 `web/assets` 下的 PNG 图片；路径会先解析再检查，不能跳出这个目录。
- 旧 `POST /api/analyze` 保持不变。

### 当前限制

- 速度只比较当前场上两只精灵；换人顺序、特性、道具、护盾尚未实现。
- 一条伤害记录只能涉及一只对方精灵；不支持“对方打对方”。
- 默认从满血开始；中途开始记录时，要先用生命变化记录设置当前生命。
- 如果游戏显示的伤害是“最多打到 0 为止”的截断值，而公式伤害超过剩余生命，这条记录可能对不上，需要按实际显示填写并人工判断。

## 完整对局日志（第二十二步）

新增 `roco_battle.py`，把零散的伤害记录升级成按回合保存的完整日志。日志是原始事实，性格/天分范围是重放后推导出来的结果。

### 数据形状

```text
battle.json
├─ version                 固定为 1
├─ initial
│  ├─ our_team[6]          我方精灵、形态、性格、天分、技能、初始能量
│  ├─ opponent_team[6]     对方精灵、形态、已见/怀疑技能、初始能量
│  ├─ active_our / active_opp
│  └─ magic_points         {our: 4, opp: 4}
├─ turns[]
│  ├─ our_action / opp_action
│  ├─ who_first            our / opp / null
│  ├─ counter              本回合是否发生应对
│  ├─ speed_inferable      本回合的先后能否用于推断速度
│  ├─ our_intended_skill / opp_intended_skill  可选：被击倒没行动时原本打算用的技能
│  ├─ events[]             damage / hp_change
│  ├─ replacements         本回合击倒后的补位
│  └─ snapshot_after       回合结束、补位完成后的全员快照
└─ result                  可选：胜方和原因
```

行动有三种：`skill`（攻击/防御/状态）、`charge`（聚能，按状态处理，恢复 5 能量）、`switch`（切换，先手 +99）。被击倒没行动时行动留空；可选填原本打算用的技能，只用于先手度判断。

每次伤害事件保存“发生时”的双方当前出战精灵状态、天气、双方印记、增减益和状态。回合结束快照保存全部 12 只精灵的生命、能量、永久/非永久增减益、状态，以及双方印记、天气剩余回合和魔力值。

### 推断规则

- 伤害：复用 `roco_team` 的候选位图筛选；额外支持防御技能的固定百分比减伤。
- 纤维化、虚化：如果本次是物攻/魔攻，分别自动补上物防/魔防 +70%（7 层），再计算伤害。
- 速度：只在没有应对、先手度相同、没有单方切换时使用；双方同时切换比较切换前场上的精灵。被击倒没行动时，必须有“原本打算用的技能”才能比较先手度。
- 第一版不建模的印记、状态、特殊防御技能、特殊攻击技能和特性，会把对应事件标记为不参与推断，只记录。
- 回合结束生命百分比、魔力值和击倒次数会做一致性检查；对不上会给出提示，不静默改数据。
- 导入/导出文件时，原始日志是唯一事实来源；推断结果可以重新计算。

### 接口

- `POST /api/battle`：请求体是整场对局日志，返回 `our_team`、`opponent_team`、`active`、`turns`、`warnings`、`snapshot`、`magic_points`、`result`。
- `GET /api/meta` 新增 `action_skills`（全部 579 个攻击/防御/状态技能）和每只精灵的 `action_skills`；旧的 `skills` 仍是 358 个攻击技能，旧页面不受影响。

### 当前限制

- 网页“对局记录”已接上 `/api/battle`，支持添加/删除回合、回合结束快照和导出/导入；`/api/team` 支持可选 `battle_log`，“当前出战”对位伤害表使用对局推断范围、当前生命/能量、双方增减益、天气和星陨。
- 技能冷却、技能位置、传动、蓄力和特殊能量技能暂不记录/不推断，但数据结构和代码预留了扩展位置。
- 特性、其他印记、状态技能的具体效果、特殊攻击技能尚未建模。

## OCR 接入（第二十五步）

OCR 是可选能力，主计算器仍然只依赖 Python 标准库。

- 独立环境：`.venv-ocr314`（RapidOCR 3.10.0、ONNX Runtime 1.32.0、OpenCV headless、Pillow、PyYAML、MSS）。模型在 `models/ocr/`，约 15 MB；环境、模型和上传缓存都被 `.gitignore` 忽略。
- `ocr_service.py`：
  - `status()` 检查虚拟环境、依赖、模型、布局和头像；
  - `run_frame()` 启动 `ocr_frame.py` 子进程识别一张静态操作帧，主服务只解析 JSON；
  - 布局只允许 `configs/ocr_*.json`，上传图片写到 `.cache/ocr_uploads/`。
- 接口：
  - `GET /api/ocr/status`：环境/模型/布局/头像状态。
  - `POST /api/ocr/frame?layout=...&our_pet=...&debug=1`：请求体是原始图片字节，返回 PR 的固定操作帧 JSON。
- 网页“OCR 操作帧”卡片：上传截图、识别双方显示名/确认身份/能量/生命/四技能/头像候选；身份确认后可把精灵和可学技能填入我方/对方队伍。不会自动写伤害或回合。
- 未实现：实时截屏监控、行动提示/伤害浮字自动归属、回合草稿确认。`windows_capture.py` 和视频复核工具仍作为独立命令行工具保留。

## 命令行用法（第六步）

基本用法：

```bash
python calc.py \
  --attacker 岚鸟 --attacker-form 本来的样子 \
  --defender 奇丽花 --skill 扇风 \
  --attacker-talents "物攻=10" --defender-talents "物防=10" \
  --power 142.5
```

带性格：

```bash
python calc.py \
  --attacker 岚鸟 --attacker-form 本来的样子 --attacker-nature 固执 \
  --defender 奇丽花 --skill 扇风 \
  --attacker-talents "物攻=10" --defender-talents "物防=10"
```

输出 JSON（便于以后前端直接调用）：

```bash
python calc.py \
  --attacker 岚鸟 --attacker-form 本来的样子 \
  --defender 奇丽花 --skill 扇风 --json
```

常用可选参数：

| 参数 | 含义 |
|------|------|
| `--level` | 等级，默认 60 |
| `--power` | 手动指定基础威力 |
| `--power-percent` | 威力百分比加成 |
| `--attack-mod` / `--defense-mod` | 攻防等级百分比 |
| `--attacker-buffs` / `--defender-buffs` | 增减益层数，例如 `魔攻=2,速度=-1`；四维每层 10 个百分点，速度每层 10 点 |
| `--starfall-layers` | 受击方身上的星陨层数（0～99）；非幻系攻击技能触发并消耗全部层数 |
| `--damage-reduction` | 减伤百分比 |
| `--damage-multiplier` | 最终伤害乘区百分比，默认 100 |
| `--weather` | 天气；目前只有 `雨天` 会提高水系技能伤害 |
| `--hits` | 连击次数，默认 1 |
| `--ignore-type-resistance` | 忽略属性抵抗 |
| `--json` | 输出完整 JSON |

## 已知限制

- 天气只实现雨天的水系技能威力 +75%；沙暴、暴风雪、雷鸣、霞光梦境只显示文本，不改伤害。
- 不包含特性、道具、场地和其他印记；目前只接入星陨印记的引爆伤害。
- 星陨的取整方式照 tzrain，尚未用游戏内数字确认；「守望星」类只消耗一半层数的特性也未实现。
- 不包含暴击和随机浮动（参考公式里没有）。
- 不校验精灵是否真的能学这个技能（未接入 `Learnsets`）。
- 速度只做到“当前场上两只精灵”的比较：显示我方具体速度、对方速度范围、技能先手值，并按“先比先手值、再比速度”给出判断；同速顺序按不确定显示。换人顺序尚未实现。
- 增减益层数目前只接入伤害计算；层数的实际上限（先按 −99～99 限制）和「护盾/免疫」等特殊规则尚未核对。
- 不包含成长星级/PVE 数值；默认按 60 级 PVP 面板。
- 威力随规则变化的技能需要手动 `--power`；数据里的 1 不代表真实威力。
- 状态/防御/特性类技能不套用伤害公式，会直接报错。
- 取整口径以 tzrain 为准；与 rocokingdom 等计算器可能有 ±1 差异。
- 性格默认「不加不减」、天分默认全 0，避免隐藏假设；实际游戏里需要显式传入。
